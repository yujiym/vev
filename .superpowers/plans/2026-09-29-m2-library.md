# M2 Clip Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clips can be registered, annotated, browsed and assembled into a track that plays — the library the decision model will later choose from.

**Architecture:** Registration is a browser step and an asynchronous one. The browser normalizes the pasted code, runs it through a reusable validation probe, records a few seconds of it, and posts the clip; the Worker stores it and enqueues annotation; a queue consumer asks **jev** the typed questions (`score`, `choice`, `noul`) that make up most of a clip's metadata, computes the palette from the recorded frames rather than from a model, and calls one small text model for the single free-text field. Tracks are ordered lists of clip ids that the M1 control panel plays.

**Tech Stack:** Drizzle + D1, R2, Cloudflare Queues, Workers AI (`typesafe/jev` and one text model), Svelte 5 + SvelteKit, Hono, valibot.

**Spec:** `docs/spec.md` — §5 (data model), §11 and §11.1 (ingestion), §11.2 (room for generated clips), §12.3 (library and track editor), §13 (permissions), §14.2 (clip licensing), §18 M2.

## Global Constraints

- `// SPDX-License-Identifier: AGPL-3.0-or-later` first line of every authored file whose format takes comments; the JSON family (`.json`, `.jsonc`) excluded. `"license": "AGPL-3.0-or-later"` in every `package.json`. English artifacts. `git commit -s`.
- **Wrangler's named environments inherit `assets` but NOT `vars`, `d1_databases`, `r2_buckets`, `queues.producers` or `queues.consumers`.** Verified three times across M0 and M1. Every binding this milestone adds is repeated under `env.preview`.
- **Bindings are named the same in every environment and differ only in what they point at** — `DB`, `MEDIA`, `INGEST`. A binding named after its resource would force the Worker to branch on its own environment, which breaks §15.3's "the deployed artifact is the one that runs at a venue".
- Cloud-only bindings stay **optional** on `Env`: `AI`, `VECTORIZE`, and now `INGEST`. `DB` and `MEDIA` are required — both have local implementations in miniflare, so local mode can satisfy them.
- **A test that compares a value against a binding, a fixture or a default must use a value distinct from that default.** M0 and M1 each shipped a test that could not tell a real read from a constant.
- Validation is valibot, `import * as v from 'valibot'`, `v.parse(schema, value)`.
- **The Access check is disabled when `VEV_MODE === 'local'`.** Local mode has no Access by design (§15.3), and the test pool runs `--env local`. Without this rule every owner-route test returns 403 and the next implementer disables the guard "temporarily" — which is how it ships disabled.
- **`Clip.id` is opaque and server-generated** (`crypto.randomUUID()` in the Worker). A client never supplies one. The human-readable `slug` is a separate, changeable field (§11.2).
- **`thumbnailKey` stores the R2 object key, never a URL.** A URL would bake the preview or production hostname into a row; the serving URL is built at read time.
- Transitions stored on tracks use the **M1 shape** — `{ kind: 'cut' | 'crossfade', bars }` from `@vev/shared`. §5's seven-type `TransitionSpec` arrives with M6's migration.
- Exact versions, not floated. Do not change the pinned `vite-plus@0.3.3`, the `vite` / `miniflare` / `workerd` overrides, or `compatibility_date`.

### Explicitly out of scope — do not start these

Each is a place where a well-meaning implementer would otherwise begin:

- **Parameter macros.** §11's "turn numeric params into macros" normalization. `params` stays `[]` this milestone.
- **Embeddings, Vectorize and the neighbour table** — M3.
- **ISF and textmode ingestion** — M8 and M9. Hydra only.
- **Per-transition settings and locks in the track editor** — M6. The editor sets order and section labels.
- **Drag to reorder.** Up/down buttons. Drag-and-drop is a later polish and a large accessibility surface.
- **Importing a clip from a URL.** Paste only.
- **The candidate panel, the chat, the decision provider chain** — M3 onward. The control panel gains "play this track" and nothing else.

## Testability boundary

- **Real tests**: everything in `packages/ingest` (normalization, dependency analysis, license extraction), the API routes under `@cloudflare/vitest-pool-workers`, the queue consumer, the palette extraction, the annotation response parsing, and the track ordering logic.
- **Manual evidence**: the registration page's probe and thumbnail recording, because they need WebGL and `MediaRecorder`. Captures go to `artifacts/<YYYY-MM-DD>-m2/` (git-ignored) and are named in the task's report. Burn a `Date.now()` overlay into anything whose timing is the claim — M1 shipped false timing evidence because it was read from the same source as the thing under test.

## Two gates that stop a task rather than stall it

- **The ingestion queues may not exist yet.** They are `vev-ingest` and `vev-ingest-preview`, created by the user with `wrangler queues create`. Task 5 needs them. If they are absent, that task reports `BLOCKED` with the exact command needed and the controller skips ahead to Task 6, returning afterwards.
- **`/api/health` is behind Cloudflare Access on the deployed preview.** Access covers the whole hostname, so the deployed health check now redirects to a login page. `scripts/smoke-live.sh` runs against `pnpm live` locally and is unaffected; **do not** try to make CI authenticate. Task 2 records the situation and the deployed-preview health check stays manual until a bypass policy exists.

The schemas are the contract three later tasks share, so they come first and they are tested first.

- [ ] **Step 1: Write the failing schema test**

`packages/shared/src/clip.test.ts` covers what the rest of the milestone depends on. At minimum:

- `newClipSchema` accepts a minimal registration payload (engine, title, code, author, license) and **rejects one carrying an `id`** — ids are server-generated (§11.2), and a schema that accepts a client id is how a client ends up choosing one.
- `license` rejects the empty string but accepts `"unknown"` (§14.2).
- `energy` accepts 1 and 5, rejects 0, 6 and 2.5.
- `motion`, `density` and `layerHint` reject a value outside their enum.
- `origin` accepts `imported`, `authored` and `generated`, and a clip whose `origin` is `generated` requires `generator`.
- `annotationStatus` accepts `pending`, `ok` and `failed`.

Use values distinct from any default in the schema.

- [ ] **Step 3: Run it to verify it fails, then write `packages/shared/src/clip.ts`**

Model §5's `Clip` with these deviations, each deliberate:

- `id` and `slug` are separate; `id` is absent from `newClipSchema`.
- `thumbnailKey?: string` replaces §5's `thumbnailUrl` — the key, not a URL.
- `annotationStatus: 'pending' | 'ok' | 'failed'` is added. §5 has no such field because it assumes annotation succeeds; §0's second principle says it must not block registration, so its outcome needs a place to live.
- `params` is present and always `[]` this milestone.
- The annotated fields (`description`, `tags`, `palette`, `energy`, `motion`, `density`, `layerHint`) are **optional**, because a clip exists before it is annotated.

Export a `clipSummarySchema` with only what a library list needs — id, slug, title, engine, tags, energy, thumbnailKey, reviewed, annotationStatus, license, commercialOk. The list endpoint returns summaries; sending whole clips to render a grid is how a library page gets slow.

Track schemas: `trackSchema` with `items: TrackItem[]` where a `TrackItem` is `{ clipId, bars?, section?, transitionIn? }`, and `transitionIn` uses `@vev/shared`'s existing `transitionSpecSchema`.

- [ ] **Step 4: Write the Drizzle schema and generate the migration**

`apps/api/src/db/clips.ts` and `tracks.ts`, re-exported from `schema.ts`. Notes that matter:

- Store `tags`, `palette`, `deps`, `params`, `generator` and `derivedFrom` as JSON text columns; SQLite has no array type and Drizzle's `text({ mode: 'json' })` handles it.
- `track_items` is its own table with a `position` integer, not a JSON blob on `tracks` — the editor reorders rows, and M6 will add per-item transition settings to them.
- Index what the library filters on: `clips.engine`, `clips.reviewed`, `clips.origin`.

Generate with `drizzle-kit generate --name library` — M0's runbook records that omitting `--name` costs a manual rename and a journal edit. Add the SPDX header to the generated `.sql`.

- [ ] **Step 5: Verify and commit**

Run `pnpm --filter @vev/shared test`, `pnpm --filter api run migrate:local`, `pnpm check`.

- [ ] **Step 2: Close the workers.dev door**

Access binds to hostnames in the user's zone, so it protects `vev-preview.0x7.sh` and **cannot** protect `vev-preview.host3.workers.dev` — which currently serves `/studio` to anyone. Set `workers_dev: false` and `preview_urls: false` in `env.preview`.

Note the trap M1 recorded: adding `routes` silently defaulted both to `false` and broke the workers.dev URL with error 1042. You are now setting them to `false` deliberately. After deploying, confirm the workers.dev hostname no longer serves the app and the custom domain still does.

- [ ] **Step 3: Verify the Access assertion in the Worker**

§13 requires the Worker to check `Cf-Access-Jwt-Assertion` as defence in depth, so a misconfigured Access application does not silently open the app. Implement it as Hono middleware over the owner routes, **not** over `/api/health` — the health route is public by design and the smoke test depends on it.

### Task 4: The registration page, the probe and the thumbnail

**Files:**
- Create: `apps/web/src/routes/studio/clips/new/+page.svelte`, `apps/web/src/lib/register-clip.ts`, `apps/web/src/lib/register-clip.test.ts`, `apps/web/src/lib/palette.ts`, `apps/web/src/lib/palette.test.ts`, `apps/api/src/routes/media.ts`, `apps/api/test/media.test.ts`
- Modify: `packages/engines/src/hydra/index.ts` (export the probe), `apps/api/src/index.ts`

**Interfaces:**
- Produces: `probeClip(code, canvas): Promise<ProbeResult>` in `@vev/engines/hydra`; `recordThumbnail(canvas, ms): Promise<Blob>`; `dominantColours(frames): string[]`; `POST /api/clips/:id/thumbnail`; `GET /media/:key`.

**A ruling this task implements, which reads as a spec violation unless you know why:** §3 says rendering happens only in the output window. The registration page nonetheless mounts its **own** `HydraCompositor` on a small canvas, because §11.1 requires the probe and the thumbnail to run in a browser and the registration screen is the browser it runs in. The rule §3 is really expressing is that *the show* renders in one place; a transient registration-time context is a different thing. It is created for the probe, used for the recording, and **disposed immediately** (§6.5 caps how many contexts may exist). Task 7 records this in the spec.

- [ ] **Step 1: The validation probe**

§11.2 requires the gate to be "a reusable probe, not a screen": *compiles, renders without errors, is not a black frame, holds its frame budget*. Put it in `@vev/engines/hydra` beside the compositor, taking a canvas and returning a structured result rather than throwing — a clip that fails to render is an expected outcome of registration, not an exception.

**The probe uses the ordinary render path, not a special one**: `load('a', code)` then `switchTo('a', { kind: 'cut', bars: 0 }, Date.now())`, exactly as the show does. A probe with its own rendering path can pass while the real one fails, which is the one thing a validation gate must not do.

The black-frame check is what stops a clip that "succeeds" while drawing nothing: sample the canvas after a few frames and require some non-zero variance, not merely non-zero pixels — a solid colour is a legitimate clip, an unchanged black buffer is not.

- [ ] **Step 2: Thumbnail recording and palette, with tests for the pure half**

`recordThumbnail` uses `canvas.captureStream()` and `MediaRecorder` to produce a few seconds of WebM (§11). It needs a browser and gets manual evidence.

`dominantColours` is **pure and tested**: given sampled pixel data, return the dominant colours as hex. Test it with synthetic frames whose answer you know — a frame that is half red and half blue returns both; a frame of one colour returns one. This is the palette, computed from what was actually rendered rather than guessed from code by a model.

- [ ] **Step 3: Upload and serve**

`POST /api/clips/:id/thumbnail` accepts the recording, writes it to `MEDIA` under a key derived from the clip id, and stores the **key** on the row. `GET /media/:key` streams it back with a long cache lifetime and a correct content type. Test both under the workers pool. The route is public, so it must serve **only keys that appear in a `clips` row** (`select 1 from clips where thumbnail_key = ?`), not merely keys under the right prefix — a prefix check alone makes any guessed UUID readable, which is a bucket lister wearing a media route's clothes.

- [ ] **Step 4: The page, then manual evidence**

The page is: paste code, run the probe, show what it found (including a failure clearly), record the thumbnail, fill in title, author and licence, save. Keep the logic in `register-clip.ts` where it is tested; the component wires elements to it (ADR 0001 — `.svelte` is outside the type gate, and M1 proved what that costs).

Register two real clips by hand — the M1 fixtures are the obvious candidates — and capture the probe result, the thumbnail and the saved row. Name the files in the report.

### Task 5: Annotation, asked as typed questions

**Files:**
- Create: `apps/api/src/ingest/annotate.ts`, `apps/api/src/ingest/annotate.test.ts`, `apps/api/src/ingest/tags.ts`
- Modify: `apps/api/src/index.ts` (add the `queue()` export), `apps/api/test/env.d.ts`

**Interfaces:**
- Produces: the queue consumer; `annotateClip(ai, clip): Promise<Annotation>`; `TAG_VOCABULARY`.

**This is the task the whole project is premised on, so it uses jev for everything jev can answer.** Most of a clip's metadata is not free text — it is a score and a set of choices — and asking a generative model for them invites drift ("kaleid" / "kaleidoscope" / "kaleidoscopic") that then breaks filtering and, in M3, search.

Verified from Cloudflare's model page on 2026-09-29: `env.AI.run('typesafe/jev', { state, questions })`; question types `choice`, `score`, `noul`; a `choice` answer carries the selected option, a confidence and per-option probabilities; `score` carries a numeric value, a confidence, a legend and per-level probabilities; `noul` carries a probability. Context is 32,000 tokens and billing is $0.042 per 1M input tokens with output free.

- [ ] **Step 1: Spike — what does jev actually return?**

`noul` is the question type this task leans on hardest and the one whose semantics the documentation states least. It "returns a probability" — of what, and what shape does the question take? Nothing establishes that yet, and the tag mechanism rests on it.

Before writing any annotation code, call the real binding once from a scratch script with one `score`, one `choice` and one `noul` question over a short Hydra clip, and **paste the raw response verbatim into your report**. Record: the exact request shape each question type needs, the exact response shape, and whether a `noul` question takes a statement, a criteria string, or something else.

Also establish whether the `AI` binding works under the local test pool. It proxies to the real service even in miniflare, so the tests will need a fake — confirm that rather than discovering it halfway through.

If the call cannot be made at all, report `BLOCKED` with the error. Everything after this step assumes the answers.

- [ ] **Step 2: Fix the tag vocabulary**

`TAG_VOCABULARY` is a fixed list of perhaps twenty tags that describe Hydra output — kaleidoscope, noise, feedback, geometric, organic, glitch, monochrome, and so on. A fixed vocabulary is the point: each tag becomes a `noul` question, the answers are probabilities, and a clip's tags are the ones above a threshold. **Export `TAG_THRESHOLD` and have the tests assert relative to it** (`TAG_THRESHOLD + 0.01` is tagged, `TAG_THRESHOLD - 0.01` is not), so the first tuning pass does not break tests that hard-coded the number. Record in a comment that the threshold and the vocabulary size are both unmeasured guesses.

- [ ] **Step 3: Write the failing annotation test**

Test `annotateClip` against a **fake `AI` binding** that returns canned jev responses in the documented shape. Prove:

- a `score` answer becomes `energy`, and a value outside 1–5 is rejected rather than stored;
- `choice` answers become `motion`, `density` and `layerHint`, and an option jev returns that is not in the enum is rejected;
- `noul` answers above the threshold become tags and those below do not;
- a malformed response — a missing field, a wrong type — results in **one retry and then `annotationStatus: 'failed'`**, never a throw that loses the clip;
- the clip's own fields are never overwritten when annotation fails.

Use canned values distinct from any default so an assertion cannot pass against a constant.

- [ ] **Step 4: Implement, including the one field jev cannot answer**

`description` is free text and structurally outside jev's shape. Call one small text model for it — `@cf/qwen/qwen2.5-coder-32b-instruct`, chosen because the input is code — and treat a failure there as it treats any other: the clip keeps its other annotations and `description` stays empty. Verify the model id against `wrangler ai models` before using it.

`palette` does **not** come from a model: it is computed in Task 4 from the recorded frames and passed in.

- [ ] **Step 5: Wire the queue consumer**

`apps/api/src/index.ts` gains a `queue()` export beside `fetch`. It reads the clip, annotates it, writes the result, and sets `annotationStatus`. A failure marks `failed` and does not retry forever — a poison message that retries indefinitely is its own outage.

Test the consumer with `cloudflare:test`'s queue helpers; **verify the helper names against the installed pool** rather than assuming them.

**If `vev-ingest` and `vev-ingest-preview` do not exist**, report `BLOCKED` with the exact `wrangler queues create` commands. Do not create them.

- [ ] **Step 6: Verify and commit**

Run `pnpm --filter api test`, `pnpm check`. Then register a clip through the real preview and confirm the annotation lands — paste the resulting row into the report, including which fields jev filled and with what confidence.
