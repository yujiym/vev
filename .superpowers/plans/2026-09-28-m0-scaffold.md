# M0 Monorepo Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the vev monorepo so that `pnpm dev` (development) and `pnpm live` (the built SPA served by a local Worker) both serve the app and the API, with licensing and CI in place from the first commit.

**Architecture:** A pnpm workspace with two apps. `apps/web` is a SvelteKit SPA (`adapter-static`, no SSR) and `apps/api` is a Hono Worker that owns every Cloudflare binding and serves `apps/web`'s build output through its assets binding — one deployed Worker, and the same artifact is what runs locally at a venue. `packages/shared` holds the Valibot schemas both sides import, so the API contract is one source of truth. Vite+ (`vp`) drives lint, format, typecheck and test from a single root config migrated from fuda-sh.

**Tech Stack:** pnpm 11 workspace, Vite+ 0.3.3 (oxlint 1.83.0 / oxfmt 0.68.0 / Vitest 4.1.11), ultracite presets, SvelteKit 2 + Svelte 5, Hono 4, Valibot 1, Drizzle ORM + D1, Wrangler 4, `@cloudflare/vitest-pool-workers` 0.22.

**Spec:** `docs/system-design.md` — §3 (architecture), §4 and §4.1 (tech stack, repository layout), §13 (security), §14.1 (licensing), §15.3 (local mode), §18 M0.

- [ ] **Step 3: Create the root Vite+ config (lint and fmt policy)**

`vite.config.ts` — this is fuda-sh's policy with the fuda-specific parts removed (no subgraphs paths, no hono/jsx pragma tags) and Svelte added:

```ts
// SPDX-License-Identifier: AGPL-3.0-or-later
/* oxlint-disable eslint/sort-keys -- sections here are ordered by topic (lint → fmt), not alphabetically */
// vev unified toolchain config (Vite+ / `vp`): test, lint (oxlint) and fmt (oxfmt)
// in one file. `vp lint` / `vp fmt` / `vp check`.
//
// Lint philosophy — near-full-strict from day one. This repo is written fresh,
// so the Ultracite presets (core + anti-slop + vitest) run UNCURATED except for
// the handful of exclusions that are structural rather than taste:
//   1. tool conflicts (a fixer/formatter fight, a framework false positive),
//   2. rules that would WEAKEN assertions,
//   3. the test-fixture latitude every codebase needs.
// Deliberate exceptions in code use `// oxlint-disable-next-line <rule> -- reason`;
// keep them rare and reasoned.
import oxfmtPreset from 'ultracite/oxfmt'
import antiSlop from 'ultracite/oxlint/anti-slop'
import core from 'ultracite/oxlint/core'
import vitest from 'ultracite/oxlint/vitest'
import { defineConfig } from 'vite-plus'

export default defineConfig({
  lint: {
    extends: [core, antiSlop, vitest],
    ignorePatterns: ['**/worker-configuration.d.ts', '**/.svelte-kit/**', '**/build/**'],
    options: {
      typeAware: true,
      typeCheck: true,
    },
    rules: {
      // -- structural exclusions (not taste) ----------------------------------
      // The fixer adds parentheses around nested ternaries; oxfmt strips them
      // again. The two tools cannot both be satisfied, in any codebase:
      'unicorn/no-nested-ternary': 'off',
      // False positive on Hono middleware (`await next()`):
      'node/callback-return': 'off',
      // False positive on Hono middleware: MiddlewareHandler's contract is
      // Response | void, so returning a Response on the early-exit path and
      // nothing on the happy path is the API:
      'typescript/consistent-return': 'off',
      // -- config, not off ----------------------------------------------------
      // Svelte components keep PascalCase names (Source.svelte); everything else kebab:
      'unicorn/filename-case': ['error', { cases: { kebabCase: true, pascalCase: true } }],
    },
    overrides: [
      // Vitest preset curation must live at override level (the preset applies
      // its rules via a test-file override, which top-level `rules` cannot beat).
      // `plugins: ['vitest']` is required here too: an override without its own
      // `plugins` list only inherits the base (non-test) `lint.plugins` list,
      // which doesn't include vitest, so `vitest/*` keys below are silently
      // dropped without it.
      {
        files: ['**/*.test.ts', '**/test/**'],
        env: { jest: true },
        plugins: ['vitest'],
        rules: {
          // These two rewrite exact `toBe(true/false)` into truthy/falsy checks —
          // they WEAKEN assertions, so they stay off even in a strict setup:
          'vitest/prefer-to-be-truthy': 'off',
          'vitest/prefer-to-be-falsy': 'off',
          // Test-fixture latitude: fakes and fixtures are built by casting.
          // All of these stay fully enforced in src:
          'typescript/no-explicit-any': 'off',
          'typescript/no-non-null-assertion': 'off',
          'anti-slop/no-chained-type-assertions': 'off',
          'anti-slop/no-unknown-parameters': 'off',
          'anti-slop/no-unknown-returns': 'off',
          'anti-slop/no-module-mocking': 'off',
          'anti-slop/require-safety-comment-for-type-assertion': 'off',
          // Same latitude for the `env as unknown as Env` casts the
          // vitest-pool-workers harness forces in test setup and fixtures:
          'typescript/no-unsafe-type-assertion': 'off',
        },
      },
      // Cloudflare Worker entry code runs in the workerd global scope:
      {
        files: ['apps/api/src/**'],
        env: { serviceworker: true },
      },
    ],
  },

  fmt: {
    // Ultracite defaults plus the vev house style.
    ...oxfmtPreset,
    svelte: true,
    printWidth: 110,
    semi: false,
    singleQuote: true,
    trailingComma: 'all',
    // Markdown prose is one paragraph per line; the viewer soft-wraps it, so a
    // reworded sentence diffs as one line rather than a reflowed block.
    proseWrap: 'never',
    ignorePatterns: [...(oxfmtPreset.ignorePatterns ?? []), '**/.svelte-kit/**', '**/build/**'],
  },
})
```

```ts
import * as v from 'valibot'

/** The two runtimes vev has: a deployed Worker, and local mode at a venue (§15.3). */
export const vevModeSchema = v.picklist(['cloud', 'local'])

/** `GET /api/health` — the one route M0 ships, and the smoke test for every later milestone. */
export const healthResponseSchema = v.object({
  ok: v.boolean(),
  mode: vevModeSchema,
  /** Short git commit of the running build; `dev` outside a release build. */
  commit: v.pipe(v.string(), v.minLength(1)),
  /** Row count of the `settings` table: proves D1 and the migrations are live. */
  settingsRows: v.pipe(v.number(), v.integer(), v.minValue(0)),
})

export type VevMode = v.InferOutput<typeof vevModeSchema>
export type HealthResponse = v.InferOutput<typeof healthResponseSchema>
```

```ts
/**
 * The Worker's binding surface.
 *
 * The cloud-only bindings are OPTIONAL on purpose: local mode (§15.3) runs the
 * same artifact with no Workers AI, no Vectorize and no queue, so every route
 * has to work with them absent. Optional here makes that a compile-time rule
 * instead of a convention.
 */
export interface Env {
  DB: D1Database
  SOURCE_URL: string
  VEV_MODE: VevMode
  SETTINGS_ENCRYPTION_KEY?: string
  AI?: Ai
  VECTORIZE?: VectorizeIndex
```

```ts
/**
 * The AGPL §13 source offer: a link to the exact commit being served (§14.1).
 * `dev` means the build carries no commit, so the link points at the repository.

export function sourceCommitUrl(sourceUrl: string, commit: string): string {

}
```

```js
const ALLOWED = new Set([
  '0BSD',
  'AGPL-3.0',
  'AGPL-3.0-only',
  'AGPL-3.0-or-later',
  'Apache-2.0',
  'BSD-2-Clause',
  'BSD-3-Clause',
  'BlueOak-1.0.0',
  'CC0-1.0',
  'GPL-3.0',

  'LGPL-2.1-or-later',
  'LGPL-3.0-or-later',
  'MIT',
  'MPL-2.0',
  'Python-2.0',
  'Unlicense',
])

const raw = execFileSync('pnpm', ['licenses', 'list', '--prod', '--json'], { encoding: 'utf8' })
const groups = JSON.parse(raw)
const offenders = []

for (const [license, packages] of Object.entries(groups)) {
  // A dual licence passes when any one of its options is allowed.
  const options = license.split(/\s+OR\s+/u).map((option) => option.replaceAll(/[()]/gu, '').trim())
  if (options.some((option) => ALLOWED.has(option))) continue

  console.error(`Disallowed dependency licences (§14.1):\n${offenders.join('\n')}`)
  process.exit(1)
}
```

- [ ] **Step 2: Write ADR 0001 — the toolchain**

`docs/adr/0001-vite-plus-toolchain.md`, in the form Context / Decision / Consequences:

- Context: vev needs lint, format, typecheck and test from day one; fuda-sh (a sibling project by the same author) runs Vite+ with the ultracite presets, so its policy can be migrated rather than re-derived. The alternative was oxlint and oxfmt as direct dependencies with SvelteKit's standard Vite and Vitest.
- Decision: Vite+ (`vp`) on the **0.3 line**, pinned to 0.3.3, with the lint and fmt policy migrated from fuda-sh's root config.
- Consequences, with the evidence measured on 2026-09-28: `vite-plus@1.0.0-rc.1` bundles Vitest 5.0.1, while `@cloudflare/vitest-pool-workers@0.22.0` declares `vitest ^4.1.0` — so the Worker test pool and Vite+ 1.0 cannot coexist yet, and 1.0 is a release candidate. `vite-plus@0.3.3` bundles Vitest 4.1.11, oxlint 1.83.0 and oxfmt 0.68.0; `ultracite@7.12.1` accepts `oxlint ^1.79.0` and `oxfmt >=0.40.0`. The three pins in `pnpm-workspace.yaml` move together. Revisit Vite+ 1.0 when the pool supports Vitest 5.
- Also record: `ErenayDev/viteplus-svelte` was used as a reference for the SvelteKit-under-Vite+ shape (the `vite@*` override and the `sveltekit()` plugin), and NOT as a template, because it ships no LICENSE and this repository is AGPL-3.0-or-later.

- [ ] **Step 3: Write ADR 0002 — the app boundary**

`docs/adr/0002-web-and-api-as-separate-packages.md`:

- Context: vev deploys as one Worker that serves the SPA from its assets binding (§3). That single artifact can be built from two packages or from one unified package using `@cloudflare/vite-plugin`.
- Decision: two packages, `apps/web` and `apps/api`, as §4.1 describes.
- Consequences: the DOM/workerd type split and the two test environments (`happy-dom`-style node tests for the SPA, `@cloudflare/vitest-pool-workers` for the Worker) fall out of the structure instead of needing per-file overrides; §15.3's rule that every route works with `AI`, `VECTORIZE` and the queue absent is enforced by `apps/api`'s own `Env` type; and stacking `@cloudflare/vite-plugin` on top of the (already novel) SvelteKit-under-Vite+ integration is avoided. The cost: two dev processes with a `/api` proxy in development, the shared API contract travelling through `@vev/shared`, and a build order (`web` before `api` deploy) that `pnpm live` and the deploy path must respect.

- [ ] **Step 4: Write ADR 0003 — the validation library**

`docs/adr/0003-valibot-for-validation.md`:

- Context: `docs/system-design.md` §4 originally named Zod. Both libraries have equivalent Hono and Drizzle integrations (`@hono/valibot-validator@0.6.1`, `drizzle-valibot@0.4.2`, both MIT), so the choice is not about capability.
- Decision: Valibot, with `import * as v from 'valibot'` as the house style. §4 was updated to match.
- Consequences: schemas tree-shake, so the SPA — which the Service Worker caches for offline use at a venue (§15.3) — ships only the validators it uses; and the vocabulary matches fuda-sh, the sibling repository this toolchain came from. The cost: Zod is the better-known library, so an external contributor (§14.1 invites them) meets an unfamiliar API; `CONTRIBUTING.md` links Valibot's documentation for that reason.
