# M1 Hydra Playback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two Hydra clips play and switch on a bar boundary, with a cut and a crossfade, rendered in a separate output window driven from a control window — and the result is reachable at a Cloudflare preview URL.

**Architecture:** All playback logic is pure TypeScript in `packages/engines`: a bar-quantised scheduler and a playback state reducer that decides *what* plays and *when* it switches. Rendering is the only impure part and happens in exactly one place — the output window — which owns a single Hydra instance acting as both compositor and clip runtime (spec §6.1). The control window holds the state, broadcasts intents with absolute `Date.now()` timestamps over `BroadcastChannel`, and the output window derives transition progress from the same clock rather than from per-frame messages.

**Tech Stack:** `hydra-synth@1.4.0` (AGPL-3.0), Svelte 5 + SvelteKit, valibot, Vite+ (`vp`), Wrangler.

**Spec:** `docs/spec.md` — §3 (separate output window), §6 and §6.1 (engine adapters, Hydra as compositor), §6.5 (WebGL contexts), §7 (playback flow), §9.1 (transition implementations), §10 (BPM), §13 (preview deployments), §18 M1.

// SPDX-License-Identifier: AGPL-3.0-or-later

/** Wall-clock timing for a performance. All timestamps are `Date.now()` milliseconds: the control and output windows are separate documents and only wall-clock values are comparable between them. */
export interface Clock {
  bpm: number
  beatsPerBar: number
  /** A moment known to be the start of a bar; every other downbeat is derived from it. */
  downbeatAt: number
}

export function barDurationMs(bpm: number, beatsPerBar = 4): number {
  return (60_000 / bpm) * beatsPerBar
}

/** Where `now` falls inside its bar, as 0 (the downbeat) up to but never including 1. */
export function barPhase(clock: Clock, now: number): number {
  const bar = barDurationMs(clock.bpm, clock.beatsPerBar)
  const offset = (now - clock.downbeatAt) % bar

  return (offset + bar) % bar / bar
}

/** The next downbeat strictly after `now`. On a downbeat it returns the following one, so "Go" pressed on the beat lands on the next bar rather than firing instantly. */
export function nextBarAt(clock: Clock, now: number): number {
  const bar = barDurationMs(clock.bpm, clock.beatsPerBar)
  const barsElapsed = Math.floor((now - clock.downbeatAt) / bar)

  return clock.downbeatAt + (barsElapsed + 1) * bar
}

/** Mean interval between taps, as a tempo. Fewer than two taps say nothing. */
export function bpmFromTaps(taps: number[]): number | undefined {
  if (taps.length < 2) return undefined

  const span = taps.at(-1)! - taps[0]!

  return 60_000 / (span / (taps.length - 1))
}
```

// SPDX-License-Identifier: AGPL-3.0-or-later
import { barDurationMs, type Clock, nextBarAt } from './clock.ts'

/** Which of the compositor's two clip buffers a clip occupies (spec §6.1: o1 and o2). */
export type Slot = 'a' | 'b'

export type TransitionKind = 'cut' | 'crossfade'

export interface TransitionSpec {
  kind: TransitionKind
  /** How long the transition takes. 0 is immediate, which is what a cut is. */
  bars: number
}

interface Loaded {
  clipId: string
  slot: Slot
}

export interface PlaybackState {
  current: Loaded
  next?: Loaded
  transition: TransitionSpec
  /** Set once Go is armed: the wall-clock moment the switch begins. */
  firing?: { at: number }
  /** Set while a crossfade is running; absent for a cut, which completes instantly. */
  fading?: { from: Slot; to: Slot; startedAt: number }
}

export type PlaybackEvent =
  | { kind: 'select-next'; clipId: string }
  | { kind: 'go'; now: number }
  | { kind: 'go-now'; now: number }
  | { kind: 'tick'; now: number }

export function initialPlayback(clipId: string, transition: TransitionSpec): PlaybackState {
  return { current: { clipId, slot: 'a' }, transition }
}

const other = (slot: Slot): Slot => (slot === 'a' ? 'b' : 'a')

export function reduce(state: PlaybackState, event: PlaybackEvent, clock: Clock): PlaybackState {
  switch (event.kind) {
    case 'select-next': {
      // The queued clip always takes the buffer the current one is not using.
      return { ...state, next: { clipId: event.clipId, slot: other(state.current.slot) } }
    }

    case 'go': {
      if (!state.next || state.firing) return state

      return { ...state, firing: { at: nextBarAt(clock, event.now) } }
    }

    case 'go-now': {
      if (!state.next) return state

      return { ...state, firing: { at: event.now } }
    }

    case 'tick': {
      return tick(state, event.now, clock)
    }

    default: {
      return state
    }
  }
}

function tick(state: PlaybackState, now: number, clock: Clock): PlaybackState {
  if (state.fading) {
    const span = barDurationMs(clock.bpm, clock.beatsPerBar) * state.transition.bars
    if (now < state.fading.startedAt + span) return state

    return complete(state)
  }

  if (!state.firing || now < state.firing.at) return state
  if (state.transition.kind === 'cut' || state.transition.bars === 0) return complete(state)

  return {
    ...state,
    fading: { from: state.current.slot, startedAt: state.firing.at, to: other(state.current.slot) },
    firing: undefined,
  }
}

/** The queued clip becomes the current one; both the armed moment and the fade are spent. */
function complete(state: PlaybackState): PlaybackState {
  if (!state.next) return { ...state, fading: undefined, firing: undefined }

  return { current: state.next, transition: state.transition }
}
```

// SPDX-License-Identifier: AGPL-3.0-or-later
import * as v from 'valibot'

/**
 * The control window holds the state and sends intents; the output window renders.
 *
 * Every moment in these messages is a `Date.now()` wall-clock millisecond, never
 * `performance.now()`: the two windows are separate documents with separate
 * performance origins, and only wall-clock values are comparable between them.
 * The output window derives transition progress from `at` itself, so a late or
 * dropped message cannot desynchronise the fade.
 */
export const OUTPUT_CHANNEL = 'vev:output'

export const slotSchema = v.picklist(['a', 'b'])

/** M1 renders two of the transitions in spec §9.1; the rest arrive with later milestones. */
export const transitionSpecSchema = v.object({
  bars: v.pipe(v.number(), v.minValue(0)),
  kind: v.picklist(['cut', 'crossfade']),
})

const clipSchema = v.object({
  code: v.pipe(v.string(), v.minLength(1)),
  id: v.pipe(v.string(), v.minLength(1)),
})

export const outputMessageSchema = v.variant('kind', [
  /** Compile a clip into a buffer. Sent before the switch that needs it (spec §7). */
  v.object({ clip: clipSchema, kind: v.literal('load'), slot: slotSchema }),
  /** Begin a transition to `to` at wall-clock `at`. */
  v.object({
    at: v.number(),
    kind: v.literal('switch'),
    to: slotSchema,
    transition: transitionSpecSchema,
  }),
  /** Tempo and downbeat, so the output window can derive bar phase itself. */
  v.object({
    beatsPerBar: v.pipe(v.number(), v.integer(), v.minValue(1)),
    bpm: v.pipe(v.number(), v.minValue(1)),
    downbeatAt: v.number(),
    kind: v.literal('clock'),
  }),
])

export type OutputMessage = v.InferOutput<typeof outputMessageSchema>
export type Slot = v.InferOutput<typeof slotSchema>
export type TransitionSpec = v.InferOutput<typeof transitionSpecSchema>
```

    expect(rewriteOut('osc(10).out()', 'b')).toBe('osc(10).out(o2)')
  })

  it('leaves whitespace inside the call alone', () => {
    expect(rewriteOut('osc(10).out( )', 'a')).toBe('osc(10).out(o1)')
  })

  it('rewrites only the final out(), so intermediate buffers keep their targets', () => {
    expect(rewriteOut('noise().out(o3)\nsrc(o3).kaleid().out()', 'a')).toBe(
      'noise().out(o3)\nsrc(o3).kaleid().out(o1)',
    )
  })

  it('appends an out() when the clip never calls one', () => {
    expect(rewriteOut('osc(10)', 'b')).toBe('osc(10).out(o2)')
  })
})
```

The "final `out()` only" rule is the decision this test locks in: a clip may legitimately write to `o3` as scratch (spec §6.1 reserves it), and only its last, argument-free `out()` is the one the compositor owns.

- [ ] **Step 3: Write the rewrite**

`packages/engines/src/hydra/rewrite.ts`:

```ts
// SPDX-License-Identifier: AGPL-3.0-or-later
import type { Slot } from '../playback.ts'

/** Slot a is Hydra's o1, slot b is o2; o0 is the compositor's final output and o3 is clip scratch (spec §6.1). */
const BUFFER: Record<Slot, string> = { a: 'o1', b: 'o2' }

const BARE_OUT = /\.out\(\s*\)/gu

/**
 * Point a clip's output at the buffer it has been given.
 *
 * Only the LAST argument-free `.out()` is rewritten: a clip may write to `o3` as
 * scratch and read it back, and those calls already name their target. A clip that
 * never calls `.out()` gets one appended, because a clip that renders nowhere is
 * indistinguishable from a broken one.
 */
export function rewriteOut(code: string, slot: Slot): string {
  const buffer = BUFFER[slot]
  const matches = [...code.matchAll(BARE_OUT)]
  const last = matches.at(-1)

  if (!last) return `${code.trimEnd()}.out(${buffer})`

  const at = last.index
  return `${code.slice(0, at)}.out(${buffer})${code.slice(at + last[0].length)}`
}
```

- [ ] **Step 5: Write the transition progress**

`packages/engines/src/transition.ts`:

```ts
// SPDX-License-Identifier: AGPL-3.0-or-later
import { barDurationMs, type Clock } from './clock.ts'
import type { TransitionSpec } from './playback.ts'

/**
 * How far through a transition `now` is, as 0 to 1.
 *
 * Derived from wall-clock timestamps rather than accumulated frame deltas, so the
 * control and output windows agree on it without exchanging a message per frame,
 * and a dropped frame does not shorten the fade.
 */
export function fadeProgress(
  spec: TransitionSpec,
  startedAt: number,
  now: number,
  clock: Clock,
): number {
  const span = barDurationMs(clock.bpm, clock.beatsPerBar) * spec.bars
  if (span <= 0) return 1

  return Math.min(1, Math.max(0, (now - startedAt) / span))
}
```

- [ ] **Step 1: Write ADR 0004**

Context: playback timing is the part of vev that cannot be debugged live — a mistimed switch is visible to an audience and gone before it can be inspected — and WebGL cannot be tested in this toolchain. Decision: all playback logic lives in a pure reducer in `packages/engines`, and the renderer only executes decisions already made; the control window owns the state and broadcasts intents with wall-clock timestamps, while the output window derives progress from the same clock. Consequences: "switches on a bar boundary" is provable by unit test rather than by eye; the control and output windows cannot drift apart when a message is late; the renderer keeps no state worth testing; and the cost is that every new transition needs its progress expressed as a pure function of time before it can be drawn.
